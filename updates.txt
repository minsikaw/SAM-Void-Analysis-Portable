=====================================================

Version: Priority 0 Traceable Analysis Pipeline v1
Timestamp: 2026-07-15 01:41:52 CEST (+0200)
Repository baseline: rfgan_phase2a_cv_flow_adapter

Purpose
-------
This version implements the Priority 0 analytical-correctness and traceability work for
SAM-based void/delamination evaluation. The changes are designed to keep detection,
quantification, review, persistence and export tied to the same immutable recipe and
stored analysis result.

Implemented changes
-------------------

1. Active recipe snapshot passed through detection and analysis
   - Added AnalysisRecipeSnapshot and AnalysisRecipeResolver.
   - A runtime snapshot now contains the selected unified preset, advanced CV parameters,
     learned sample/TSV geometry and disposition thresholds.
   - Production detection, batch analysis, ROI review and color quantification receive a
     cloned snapshot instead of silently reading unrelated mutable settings.
   - Recipe snapshot ID and SHA-256 are attached to detections, ROI corrections and results.

2. Calibration preview separated from publishing
   - Preview and live-update runs are now in-memory operations only.
   - Loading a JSON preset opens it for preview without importing or activating it.
   - "Publish preset" explicitly versions, hashes, saves and activates the configuration.
   - Published presets embed advanced detector parameters, learned geometry and the
     whole-sample decision threshold.

3. Non-destructive project rescanning
   - Project scanning no longer clears ROI corrections or delamination analysis results.
   - Manually overridden ROIs are retained and are not replaced by scan-time auto detection.
   - Auto-detection metadata is refreshed only for samples without a manual override.
   - Existing analysis history remains available when project inputs are rescanned.

4. DelamAnalysisStore made authoritative
   - The store now keeps every analysis run and exposes the latest run per sample.
   - Excel export reads persisted results only and performs no image re-analysis.
   - Annotated composite export uses the persisted result, method and analysis settings.
   - Export is blocked when mapped analytical input hashes differ from the stored run,
     requiring re-analysis while preserving the previous history.

5. Sample and TSV polygons preserved and quantified
   - Sample and TSV polygons are retained by the advanced detector and ROI correction store.
   - Manual sample corrections preserve/regenerate polygon geometry.
   - Mask and color-range quantification use polygon masks, with rectangle fallback only for
     legacy data.
   - TSV measurements are clipped to the sample polygon.
   - Review and annotated-output overlays render the stored polygons.

6. Input, recipe, settings and result versioning/hashing
   - Added SHA-256 hashing for raw, mask, label and effective detection inputs.
   - Added recipe content hash, analysis-settings hash and result-integrity hash.
   - Added immutable analysis run IDs, UTC timestamps and complete run history.
   - Analysis result/storage schema advanced to version 3.
   - Manual decision edits recalculate the persisted result hash.

7. Hard-coded global failure threshold removed
   - DelamAnalysisService now evaluates DelamDecisionThresholds from the active recipe.
   - Whole-sample threshold is editable in Calibration Studio and saved on publish.
   - An optional TSV-specific threshold is supported by the data model and decision engine.
   - The legacy 5% value remains only as a migration/default value for old presets; it is no
     longer hard-coded inside the analysis decision method.

Additional export/review improvements
-------------------------------------
- Excel output now includes current results, complete analysis-run history and export metadata.
- Exported fields include method, automatic/final decision, manual override, thresholds,
  polygon vertex counts, recipe/version/hash, input hashes, settings hash, result hash,
  timestamps, warnings and current input-integrity status.
- Analysis review details now display recipe and result provenance.
- Stored mask threshold or color settings are reused when reconstructing result previews.

CV CALIBRATION STUDIO STACK OVERFLOW + SAMPLE GUARD FIX
Timeline stamp: 2026-07-27 13:41:43 CEST (Europe/Berlin)
Version: rfgan_priority0_traceable_analysis_v1_calibration_stack_fix
================================================================================

Issue investigated
------------------
Opening CV Calibration Studio with a selected sample could terminate with:

System.StackOverflowException (0x800703E9)

The debugger could appear to stop near GetCombo<T>() while reading calibration controls,
but GetCombo<T>() was not the root cause.

Root cause
----------
SynchronizeActivePresetFromUi() called BuildAdvancedGeometryFromCalibrationUi().
BuildAdvancedGeometryFromCalibrationUi() then called SynchronizeActivePresetFromUi()
again. This produced an infinite synchronous recursion while the calibration preview was
being prepared, eventually exhausting the process stack.

Changes made
------------
1. Removed the recursive synchronization call from
   BuildAdvancedGeometryFromCalibrationUi(). The method now builds a geometry snapshot
   only and does not mutate/synchronize the active preset.

2. Added a _calSynchronizingPreset re-entry guard around
   SynchronizeActivePresetFromUi(). This protects the form from future accidental
   synchronization cycles.

3. Added controlled calibration-run exception handling:
   - logs the failing image and run identifier;
   - displays a readable CV Calibration Studio error message;
   - restores the Run / Apply button in a finally block;
   - ignores stale errors/results from superseded live-update runs.

4. Added sample-selection and image-availability guards in MainForm:
   - uses the actively selected row;
   - falls back to one checked sample when exactly one is checked;
   - displays "Please select a sample first" when no unambiguous sample exists;
   - warns when the selected sample has no raw or detection image;
   - catches ordinary form-opening errors and logs the sample/image context.

5. Added equivalent defensive handling in SampleDetectionReviewForm:
   - informs the user when no sample is selected;
   - validates the raw/detection image before opening the studio;
   - logs and reports ordinary initialization/opening failures.

Modified files
--------------
- Forms/SampleDetectorTestForm.Calibration.cs
- Forms/SampleDetectionReviewForm.cs

- updates.txt

Validation notes
----------------

WORKSPACE SAVE / AUTOSAVE + ROI DRAFT RECOVERY FEATURE
Timeline stamp: 2026-07-27 14:21:00 CEST (Europe/Berlin)
Version: rfgan_priority0_traceable_analysis_v1_workspace_autosave
================================================================================

Purpose
-------
Added a project-scoped workspace persistence system that can restore the user's current
working context after closing, restarting or recovering from a failure. The implementation
runs inside the application as a single background writer rather than as a second process.

Workspace data saved
--------------------
- Project root and project name.
- Sample, label, mask, detection, ZGT/raw-source and output folder references.
- Current sample mapping and the source file locations associated with each sample.
- Checked samples and the currently active sample.
- Active workflow tab, filter, sample type and selected preset/workflow state.
- References to the authoritative ROI-correction and delamination-analysis stores.
- Unconfirmed sample/TSV ROI rectangle edits, including X, Y, width and height.
- Source-image dimensions and SHA-256 identity for validating recovered ROI drafts.

Architecture
------------
1. Added a versioned WorkspaceState model and dedicated path/state models.
2. Added WorkspaceStateService as the one in-process workspace coordinator:
   - one serialized writer protected by SemaphoreSlim;
   - 1.2-second debounce after related UI changes;
   - 60-second checkpoint only while the workspace is dirty;
   - immutable cloned snapshots before background serialization;
   - immediate checkpoints for important operations;
   - final synchronous flush during application shutdown.
3. Added WorkspaceStateStore for atomic JSON persistence:
   - writes to workspace_state.json.tmp;
   - retains workspace_state.json.bak;
   - replaces the active file atomically where supported;
   - falls back to the backup when the main file cannot be loaded.
4. Added WorkspacePathResolver so file locations are saved relative to the project root
   with absolute-path fallbacks. This allows a project to be moved or reopened on another
   drive more reliably.
5. Added a small recent-workspace pointer under LocalAppData so the application can offer
   to restore the last workspace at startup.

Workspace location
------------------
Default project workspace:
  <ProjectRoot>\Outputs\_Workspace\workspace_state.json

Associated recovery files:
  workspace_state.json.bak
  workspace_state.json.tmp

Recent-workspace pointer:
  %LocalAppData%\RFGAN.SampleMapper\recent_workspace.json

User-interface changes
----------------------
- Added Save workspace.
- Added Save workspace as.
- Added Open workspace.
- Added an autosave status indicator for saved, saving, unsaved and error states.
- Added a startup prompt for restoring the most recent workspace.
- Added project-root relinking when a restored project has moved.
- Missing files are resolved from project-relative paths first and absolute fallbacks second.

Autosave triggers
-----------------
Autosave is requested after meaningful state changes rather than on a continuous polling
loop. Triggers include folder/project changes, sample checks, active-sample changes,
workflow/preset changes, mapping updates, scan completion, review/calibration entry and ROI
editing. Rapid changes are coalesced by the debounce timer to avoid excessive disk writes.

ROI draft recovery
------------------
- Sample and TSV rectangle changes are captured as unconfirmed workspace drafts.
- Dragging/resizing requests a debounced update, with an immediate checkpoint on mouse-up.
- Drafts are validated against project, sample position, source dimensions and image hash.
- A valid newer draft is restored with the visible state:
    "ROI source: Recovered autosaved edit (not yet confirmed)"
- Confirming a manual ROI continues to save through RoiCorrectionStore, which remains the
  authoritative correction source.
- After confirmation, the corresponding pending workspace draft is removed.
- Existing confirmed ROI corrections and analysis results are not duplicated into the
  workspace file, preventing conflicting sources of truth.

Additional reliability changes
------------------------------
- Grid refresh now preserves checked samples and the active sample using stable project/
  position keys rather than row indices.
- Selecting a different project clears the previous in-memory mapping before the new
  workspace is captured.
- RoiCorrectionStore now uses temporary/backup files and can recover from its backup when
  the main correction JSON is unreadable.
- Autosave errors are logged and reported through the status indicator without terminating
  the active image-analysis workflow.

2026-07-27 14:26:44 CEST - Workspace checkpoint Timer ambiguity build fix
================================================================================
Issue
-----
The workspace autosave build failed with CS0104 because `Timer` resolved ambiguously
between `System.Windows.Forms.Timer` and `System.Threading.Timer`. The project uses
WinForms implicit/global namespaces while WorkspaceStateService.cs also imports
System.Threading, so the unqualified type name was not unique.

Root cause
----------
WorkspaceStateService uses a 60-second background safety checkpoint with a callback and
thread-pool execution. That behavior belongs to System.Threading.Timer; it is not a UI
message-loop timer. Both the field declaration and constructor call used the unqualified
name `Timer`.

Changes
-------
- Changed the checkpoint field to `System.Threading.Timer`.
- Changed the checkpoint constructor to `new System.Threading.Timer(...)`.
- Kept existing System.Windows.Forms.Timer declarations in calibration and ZGT forms
  explicitly qualified; those are UI timers and require no change.
- Searched the complete C# source tree for unqualified Timer declarations/usages. No
  additional ambiguous Timer references remain.

Validation
----------
- Verified WorkspaceStateService now consistently uses System.Threading.Timer.
- Verified UI timer users remain explicitly typed as System.Windows.Forms.Timer.
- Verified no standalone `Timer` field declarations or constructor calls remain.

Build limitation
----------------
The repository was source-validated in this container. A complete Windows WinForms build
still needs to be run in Visual Studio/.NET 8 on the target development machine.
